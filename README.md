# Pake 本地打包工作区说明

这个目录是我帮你整理好的本地 Pake 工作区。

## 目录结构

- `cli`
  - 本地 Pake CLI 和 Tauri 源码
  - 只有在“开发、改注入脚本、重新打包”时才需要
- `projects`
  - 每个项目一个独立文件夹
  - 你平时主要就在这里改
- `releases`
  - 用来放便于集中查看的成品
  - 如果某个 exe 正在运行，脚本可能跳过覆盖这里的同名文件

## 你平时最常用的流程

以 `projects\edogex-api-stats` 为例：

1. 修改 `project.json`
   - 主要改这里的 `url`
2. 如需定制页面样式或逻辑，再改：
   - `inject.css`
   - `inject.js`
3. 双击下面任一脚本：
   - `双击-仅打包.cmd`
   - `双击-打包并打开.cmd`
4. 成品输出在：
   - `dist`

## 每个项目目录里几个文件是干什么的

- `project.json`
  - 项目基础配置
  - 常改：`url`、名称、窗口尺寸、exe 名
- `inject.css`
  - 注入到网页里的 CSS
- `inject.js`
  - 注入到网页里的 JS
- `双击-仅打包.cmd`
  - 只构建，不自动打开
- `双击-打包并打开.cmd`
  - 构建完成后自动启动成品
- `双击-打开当前成品.cmd`
  - 不重新构建，直接打开当前 `dist` 里的 exe
- `dist`
  - 当前项目最新可分享成品

## 分享给别人时发什么

只需要发下面任一成品，不需要发 `cli`：

- `dist` 里的 `.exe`
- `dist` 里的 `.msi`

## 修改 URL 之后到底点哪个

如果你刚改完 `project.json` 里的 `url`：

- 想“重新打包但先不打开”，双击 `双击-仅打包.cmd`
- 想“重新打包并立即看效果”，双击 `双击-打包并打开.cmd`

如果你已经打包过，只想再次启动当前成品：

- 双击 `双击-打开当前成品.cmd`

## 备注

- 运行中的 exe 会占用文件，所以 `releases` 目录里同名 exe 有时不会被覆盖
- 这不影响 `dist` 里的最新成品生成
- 真正以当前最新打包结果为准的，优先看 `dist`
